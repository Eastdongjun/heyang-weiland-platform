## 第一部分：系统架构总览

### 1.1 系统分层

```
┌──────────────────────────────────────────────────────┐
│                  展示层（政府端）                      │
│  Vue 3 + TypeScript + Element Plus                   │
│  适配 PC 浏览器 (1920×1080) 和 电视 (3840×2160)      │
├──────────────────────────────────────────────────────┤
│                  展示层（巡逻端）                      │
│  Flutter / uni-app（一套代码 iOS + Android）          │
├──────────────────────────────────────────────────────┤
│                  API 网关层                           │
│  Nginx / Kong → 统一鉴权 + 路由 + 限流               │
├──────────────────────────────────────────────────────┤
│                  业务服务层                           │
│  视频服务 │ AI服务 │ 设备服务 │ 告警服务 │ 工单服务    │
│  GIS服务  │ 用户服务 │ 通知服务 │ 无人机服务          │
├──────────────────────────────────────────────────────┤
│                  数据层                               │
│  PostgreSQL（业务数据）│ Redis（缓存/队列）            │
│  MinIO（对象存储：录像/图片）│ TDengine（时序数据）     │
│  Elasticsearch（日志/搜索）                          │
├──────────────────────────────────────────────────────┤
│                  设备接入层                           │
│  GB/T 28181 / ISUP / RTSP（摄像头）                  │
│  MQTT（传感器）│ DJI Cloud API（无人机）              │
└──────────────────────────────────────────────────────┘
```

### 1.2 技术栈明细

| 层次 | 技术选型 | 版本要求 | 选型理由 |
|:----|:---------|:--------|:---------|
| PC前端 | Vue 3 + TypeScript + Element Plus | Vue 3.4+, TS 5+ | 政府项目生态成熟，社区活跃 |
| 电视适配 | 同一套 Vue 代码，CSS 响应式 | - | 非独立开发，适配分辨率即可 |
| 移动端 | Flutter / uni-app | Flutter 3+ | 一套代码双端，离线能力好 |
| 地图 | 天地图 WebGL API | - | 国产要求 |
| 后端 | Java 17+ / Spring Boot 3.x | Spring Boot 3.2+ | 稳定、成熟、政务项目主流 |
| AI服务 | Python 3.11+ / FastAPI | FastAPI 0.110+ | AI生态丰富，异步高性能 |
| 流媒体 | SRS / ZLMediaKit | SRS 6+ | 国产开源流媒体，GB28181支持好 |
| 数据库 | PostgreSQL 15+ | - | 关系型数据 |
| 时序库 | TDengine 3+ | - | 国产时序库，IoT场景适配 |
| 缓存 | Redis 7+ | - | 会话/队列/缓存 |
| 对象存储 | MinIO | - | 兼容S3，私有部署 |
| 消息队列 | RabbitMQ | - | 工单/设备消息 |
| 日志 | ELK / Loki | - | 集中日志 |

### 1.3 两个终端的技术差异

| 维度 | 政府端 | 巡逻端 |
|:----|:------|:-------|
| 运行环境 | PC浏览器 (Chrome/Edge) | 手机 App / 小程序 |
| 核心技术 | Vue 3 + TS + Element Plus | Flutter / uni-app |
| 分辨率 | 1920×1080 ~ 3840×2160 | 手机自适应 |
| 网络 | 政府内网/专线，稳定 | 4G/5G，可能断网 |

| 离线能力 | 不需要 | **必须**（离线缓存+队列） |

```sql
-- 用户表
CREATE TABLE sys_user (
    id              BIGSERIAL PRIMARY KEY,

CREATE TABLE sys_role (
    id              BIGSERIAL PRIMARY KEY,
    name            VARCHAR(64) NOT NULL UNIQUE,     -- 角色名称

    description     VARCHAR(255),
    created_at      TIMESTAMP DEFAULT NOW()
);

-- 菜单权限表
CREATE TABLE sys_menu (
    id              BIGSERIAL PRIMARY KEY,
    parent_id       BIGINT,                          -- 父菜单
    name            VARCHAR(64) NOT NULL,             -- 菜单名称
    path            VARCHAR(128),                     -- 前端路由

-- 角色-菜单关联
CREATE TABLE sys_role_menu (
    role_id         BIGINT NOT NULL,
```

```sql
-- 告警表
CREATE TABLE alarm (
    id              BIGSERIAL PRIMARY KEY,
    alarm_code      VARCHAR(64) NOT NULL UNIQUE,       -- 告警编号 AL-20260509-0001
    level           SMALLINT NOT NULL,                  -- 1:一级(火灾) 2:二级(疑似) 3:三级(环境) 4:四级(设备)
    source_type     SMALLINT NOT NULL,                  -- 告警来源: 1:热成像 2:烟雾识别 3:无人机 4:传感器 5:移动侦测 6:越界
    device_id       BIGINT REFERENCES device(id),
    description     VARCHAR(500),                       -- 告警描述
    location_desc   VARCHAR(255),                       -- 位置描述
    longitude       DECIMAL(10,6),
    latitude        DECIMAL(10,6),
    temperature     DECIMAL(5,1),                       -- 温度值（热成像时）
    confidence      DECIMAL(5,2),                       -- 置信度
    snapshot_url    VARCHAR(500),                       -- 告警截图URL
    status          SMALLINT DEFAULT 0,                 -- 0:未处理 1:确认中 2:已派单 3:已处理 4:误报
    confirmed_by    BIGINT REFERENCES sys_user(id),     -- 确认人
    confirmed_at    TIMESTAMP,                          -- 确认时间
    false_alarm_reason VARCHAR(255),                    -- 误报原因
    created_at      TIMESTAMP DEFAULT NOW(),
    updated_at      TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_alarm_level_status ON alarm(level, status);
CREATE INDEX idx_alarm_created_at ON alarm(created_at);

-- 告警截图表
CREATE TABLE alarm_snapshot (
    id              BIGSERIAL PRIMARY KEY,
    alarm_id        BIGINT NOT NULL REFERENCES alarm(id),
    image_url       VARCHAR(500) NOT NULL,              -- 截图URL（MinIO）
    thumbnail_url   VARCHAR(500),                       -- 缩略图URL
    type            SMALLINT DEFAULT 1,                  -- 1:可见光 2:热成像
    created_at      TIMESTAMP DEFAULT NOW()
);

-- 工单表
CREATE TABLE work_order (
    id              BIGSERIAL PRIMARY KEY,
    order_code      VARCHAR(64) NOT NULL UNIQUE,        -- 工单编号 WO-20260509-0001

    title           VARCHAR(255) NOT NULL,               -- 工单标题
    priority        SMALLINT DEFAULT 2,                  -- 1:紧急(红色) 2:普通(蓝色)
    status          SMALLINT DEFAULT 0,                  -- 0:待派发 1:处理中 2:待审核 3:已完成 4:已归档
    dispatch_type   SMALLINT,                            -- 1:自动派发 2:人工指派

    assigned_at     TIMESTAMP,                           -- 派发时间
    accepted_at     TIMESTAMP,                           -- 接单时间
    departed_at     TIMESTAMP,                           -- 出发时间
    arrived_at      TIMESTAMP,                           -- 到达现场时间
    completed_at    TIMESTAMP,                           -- 完成时间
    result          SMALLINT,                            -- 处置结果: 1:已处理 2:误报 3:需支援 4:无法到达
    description     TEXT,                                -- 处置描述
    longitude       DECIMAL(10,6),                       -- 现场经纬度
    latitude        DECIMAL(10,6),
    reviewer_id     BIGINT REFERENCES sys_user(id),      -- 审核人
    review_comment  VARCHAR(500),                        -- 审核意见
    reviewed_at     TIMESTAMP,

CREATE INDEX idx_wo_status ON work_order(status);
CREATE INDEX idx_wo_assignee ON work_order(assignee_id);

-- 工单附件表
CREATE TABLE work_order_attachment (

-- 工单状态变更日志
CREATE TABLE work_order_log (
```

## 第三部分：核心业务流程状态机

### 3.1 告警状态机

```
                    ┌──────────┐
                    │  未处理   │ ← 新建告警进入此状态
                    └────┬─────┘
                         │
                    ┌────▼─────┐
              ┌─────│ 确认中    │──────┐
              │     └────┬─────┘      │
              │          │            │
         ┌────▼────┐  ┌─▼────────┐  ┌▼──────┐
         │ 已派单   │  │  误报    │  │  已处理 │
         └────┬────┘  └──────────┘  └───────┘
              │
         ┌────▼────┐
         │ 已处理   │（由关联工单完成时触发）
         └─────────┘
```

**规则：**
- 一级/二级告警自动创建工单，状态→已派单
- 三级告警可选创建工单
- 误报必须选原因，存入误报样本库
- 工单完成时告警状态自动同步

### 3.2 工单状态机

```
                    ┌──────────┐
                    │  待派发   │ ← 自动或人工创建后
                    └────┬─────┘
                         │ 派发
                    ┌────▼─────┐
                    │  处理中   │ ← 巡逻员点击"开始处置"
                    └────┬─────┘
                         │ 提交反馈
                    ┌────▼─────┐
               ┌────│  待审核   │
               │    └────┬─────┘
               │         │
          ┌────▼────┐  ┌─▼────────┐
          │ 已完成   │  │  驳回    │──→ 退回处理中
          └────┬────┘  └──────────┘
               │ 归档
          ┌────▼────┐
          │ 已归档   │
          └─────────┘
```

**规则：**
- 待派发超过30分钟无人接单 → 提醒管理员
- 巡逻员提交后不可修改
- 管理员驳回需填原因
- 归档后只读

### 3.3 巡逻员位置监控

```
巡逻员App每30秒上报一次位置（经纬度+时间戳）
    │
    ├── 超过30分钟未上报 → 产生"人员异常"告警（四级）
    │
    └── 超过60分钟未上报 → 告警升级为紧急（二级）
    
触发条件仅在巡逻员"在岗时段"有效
（非下班时间、非请假状态不触发）
```

## 第六部分：关键业务规则（开发者必须注意）

### 6.1 告警规则引擎（简单版本）

```
规则存储格式（JSON）：
{
    "name": "火灾告警规则",
    "enabled": true,
    "conditions": [
        { "sensor": "temperature", "operator": ">=", "value": 35 },
        { "sensor": "smoke_confidence", "operator": ">=", "value": 0.7 }
    ],
    "logic": "AND",
    "result_level": 1,
    "result_desc": "温度超标且检测到烟雾，判定为一级火警"
}
```

**注意**：不需要做成通用规则引擎，仅支持预设模板+阈值引用。
- 开发时预置3条规则，写在配置文件中
- 用户可通过后台修改阈值（B-10），规则逻辑不变
- V1.0不提供可视化规则编辑界面

### 6.2 工单自动派发算法

```
综合得分 = 距离得分(0-100) × 0.6 + 负载得分(0-100) × 0.4

距离得分：
  - 计算告警点与巡逻员当前位置的直线距离
  - 距离<500m → 100分
  - 距离500m-2km → 线性递减
  - 距离>2km → 0分

负载得分：
  - 当前处理中工单数 = 0 → 100分
  - 当前处理中工单数 = 1 → 60分
  - 当前处理中工单数 >= 2 → 0分

选择综合得分最高的巡逻员，推荐给管理员确认。
```

### 6.3 4G流量告警逻辑

```
每月1日重置流量计数
当 used_bytes / total_bytes >= 0.8（80%）时：
  → 发送App推送+短信告警（每日最多1次，不重复发送）
  → alarm_sent_80 = true

当 used_bytes / total_bytes >= 1.0（100%）时：
  → 发送紧急告警至指挥中心（App推送+短信+PC弹窗）
  → alarm_sent_100 = true
```

### 6.4 巡逻员失联判断逻辑

```
只对"当班"巡逻员生效（M-07位置上报开启状态）

每隔1分钟检查一次：
  SELECT * FROM sys_user 
  WHERE role_code = 'RANGER' 
    AND status = 1 
    AND NOW() - last_position_time > INTERVAL '30 minutes'
  
  如果有结果 → 生成四级告警（人员异常）
  如果 NOW() - last_position_time > INTERVAL '60 minutes'
   → 将该告警升级为二级
```

### 6.5 大屏演示模式数据隔离

```
演示模式标志：sessionStorage.setItem('demo_mode', true)

演示模式下：
  - 所有告警触发使用模拟数据，不写入正式表
  - 工单创建使用模拟数据，隔离存储
  - 退出演示模式时清空所有模拟数据
  - 演示模式下页面有明显的"演示模式"水印标识

实现方案：
  - API层新增 /demo/* 路由，使用独立的数据源（内存Map或临时表）
  - 前端在demo_mode=true时请求/demo/接口
```

## 第七部分：关键非功能需求的技术实现要点

### 7.1 视频流播放

```
内网摄像头：
  流媒体服务器(SRS)拉RTSP流 → 转WebRTC → 浏览器播放
  延迟目标：≤3秒

4G摄像头：
  设备通过ISUP注册到流媒体服务器 → 服务器拉流 → 转WebRTC/HLS
  延迟目标：≤5秒（受物理链路限制）

无人机直播：
  DJI遥控器→RTMP推流→SRS转WebRTC→浏览器播放
  延迟目标：≤2秒

播放器选型推荐：西瓜播放器(XGPlayer) / Video.js
```

### 7.2 离线能力（巡逻端App）

```
本地数据库：SQLite
同步策略：增量同步（基于 updated_at 时间戳）
冲突策略：Last-Write-Win（以最新的为准）
存储上限：离线缓存 ≤200MB，超限自动清理最早7天前的数据
触发同步：网络恢复时自动 + 下拉刷新手动

离线数据清单：
  - 已打开的工单详情（文字+缩略图）
  - 已打开的告警信息
  - 个人档案
  - 离线地图瓦片（预下载）
```

### 7.3 天地图使用注意事项

```
坐标系：WGS-84（所有设备经纬度统一使用此坐标系）
API Key：需向自然资源部申请天地图开发者Key
底图类型：支持矢量底图和卫星影像两种
离线方案：移动端可预下载天地图离线瓦片包（约200MB）
注意事项：
  - 天地图在缩放级别15以上详细度足够
  - 涉及湿地边界数据需从当地自然资源局获取
```

### 7.4 安全性实现要点

```
1. 密码存储：bcrypt，cost factor >= 12
2. Token：JWT，过期时间24小时，刷新Token 7天
3. API鉴权：除/auth/login和/health外，所有接口需Token
4. SQL注入防护：所有数据库查询使用MyBatis参数绑定，禁止拼接SQL
5. 视频流加密：RTMPS优先，降级为RTSP over TLS
6. 日志不可篡改：使用追加写入模式，日志文件设为只读权限
7. 操作日志：所有写操作（增/删/改）记录到 sys_operation_log
```
