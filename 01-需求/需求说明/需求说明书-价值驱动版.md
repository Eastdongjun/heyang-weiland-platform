# 合阳洽川湿地智慧管理平台 — 价值驱动需求说明书

> **版本**: V1.2（明确了两个终端形态：政府端PC/电视 + 巡逻端App）
> **总条目**: 96 项
> **日期**: 2026-05-09

## 第一部分：为什么做这个系统

### 1.1 系统的两个终端

这个系统只有**两个终端**，没有第三个：

```
┌─ 政府端 ───────────────────────────────────────────┐
│  部署在政府办公室，同一套Web界面                      │
│  ├─ 管理员/指挥员用电脑打开 → 日常操作（鼠标键盘）   │
│  └─ 领导用电视打开 → 视察展示（大屏显示，不操作）    │
│  大屏不是单独开发的系统，是同一套界面适配电视分辨率    │
└────────────────────────────────────────────────────┘

┌─ 巡逻端 ───────────────────────────────────────────┐
│  巡逻员手机上的App（或小程序）                       │
│  核心功能：收任务、导航到现场、拍照反馈、提交结果      │
└────────────────────────────────────────────────────┘
```

### 1.2 背景：从零开始

合阳洽川湿地目前**没有监控系统、没有物联设备、没有统一管理平台**。防火靠人瞭望，巡逻靠人走路，设备状态靠人去检查。

这个系统要从零建一套完整的**感知→监控→告警→响应→展示**体系。

### 1.2 领导视察时会看什么

| 领导关注点 | 具体问什么 | 系统要怎么证明 |
|:----------|:----------|:--------------|
| **系统完整性** | "这套系统都能干什么？" | 各模块完整演示：监控→告警→派单→处置→归档，全链路跑通 |
| **运行状态** | "设备都在线吗？系统稳定吗？" | 大屏上展示：设备在线率、系统运行时长、今日告警统计 |
| **应急能力** | "真出事能响应吗？" | 从告警触发到工单派发到人员到场，全流程可演示 |
| **实际价值** | "花了这些钱，带来了什么改变？" | 以前靠人、现在靠系统的对比数据 |

### 1.3 合阳湿地的真实痛点

| 痛点 | 谁最疼 | 现在怎么处理的 | 后果 |
|:----|:------|:-------------|:-----|
| 火情靠人发现，等看到烟已经烧大了 | 指挥中心 | 人工瞭望+群众报警 | 错过最佳灭火时机 |
| 巡逻人员去了现场，指挥中心不知道到了没、处理了没 | 指挥中心 | 打电话问 | 信息黑洞 |
| 设备坏了没人知道，等发现时已经坏了好几天 | 维护员 | 定期巡检 | 监控盲区 |
| 领导来视察，只能口头汇报"管得不错" | 领导 | PPT演示 | 拿不出数据 |
| 4G摄像头流量超限停机，关键时期掉链子 | 管理员 | 事后才发现 | 监控断档 |

### 1.2 系统要解决的核心问题

```
一句话：让湿地管理从"人盯人"变成"数据驱动"
```

具体来说：
- **以前**：火情靠人发现 → 打电话叫人 → 人去现场看 → 回来报告
- **以后**：设备自动发现 → 系统派单 → 人去确认反馈 → 数据自动归档

### 1.3 成功的标准（上线一年后看这些）

| 指标 | 以前（没有系统） | 目标 |
|:----|:---------------:|:----:|
| 火情发现方式 | 人瞭望 | **系统自动发现** |
| 火情响应时间 | 1-2小时 | ≤30分钟 |
| 领导视察能展示什么 | 口头汇报 | **全链路现场演示** |
| 设备状态 | 不知道 | 实时在线率看得见 |
| 巡逻轨迹 | 不知道人去了哪 | 全程可追溯 |
| 4G流量超限停机 | 每年2-3次 | 0次 |

## 第二部分：谁用这个系统

### 👤 角色一：指挥中心值班员（核心用户）

**日常画风**：8小时盯着屏幕，同时监控多个画面，告警来了要快速响应。

| 他最痛的事 | 系统怎么帮他 |
|:-----------|:------------|
| 告警太多分不清轻重 | AI分级：一级火警红色弹窗+声音，三级环境告警安静列表显示 |
| 不知道巡逻员到哪了 | 地图上实时显示位置 + 超过30分钟不动自动告警 |
| 换班时上一班有什么没处理 | 自动生成交接清单，接班人在系统上签收 |
| 晚上值班大屏太刺眼 | 19:00后自动切深色模式 |

**他的核心流程**：
```
看监控 → 告警弹窗 → 确认告警 → 派工单 → 看巡逻员接单 → 等反馈 → 审核归档
```

### 👤 角色二：一线巡逻员（每天在湿地走）

**日常画风**：在湿地巡走，信号时好时坏，手上可能拿着工具。

| 他最痛的事 | 系统怎么帮他 |
|:-----------|:------------|
| 接到工单不知道具体位置 | 一键导航到告警点 |
| 信号差的地方打不开工单 | 离线缓存，没网也能看 |
| 拍照后回去再上传太麻烦 | 离线队列，有网自动传 |
| 一个人巡湿地心里没底 | 紧急求助一键发位置到指挥中心 |
| 走了半天别人不知道你在哪 | 自动上报轨迹，指挥中心能看到 |

**他的核心流程**：
```
收到任务 → 查看详情 → 导航前往 → 现场拍照 → 填写结果 → 提交
```

### 👤 角色三：管理员（管设备、管人、管配置）

**日常画风**：保证系统正常跑，设备在线，流量不超。

| 他最痛的事 | 系统怎么帮他 |
|:-----------|:------------|
| 摄像头离线了不知道 | 离线5分钟自动弹窗 |
| 4G流量超限停机才反应过来 | 用到80%就告警 |
| 设备该维护了没人记得 | 维保计划到期自动提醒 |
| 误报太多不知道调哪个阈值 | 误报率统计，告诉你是哪个设备、哪种告警误报最多 |

### 👤 角色四：领导（来看成果的）

**日常画风**：偶尔来视察，站大屏前看5分钟。

| 他最关心的 | 大屏上要展示什么 |
|:-----------|:----------------|
| 湿地安全吗？ | 实时告警数 + 处置率 + 设备在线率 |
| 管得好不好？ | 本月告警趋势 + 平均响应时间 |
| 投入值不值？ | 系统运行状态 + 关键数据看板 |
| 有没有亮点？ | 大屏要大气、数据要好看、一眼能看懂 |

## 第三部分：功能需求（按价值流组织）

### 价值流一：防火闭环（从发现到处置完成）

**为什么这是第一条**：合阳湿地最大的风险是火灾。早发现一分钟，少烧一片林。

```
热成像/烟雾检测 → 告警生成 → 自动截图 → 创建工单 → 派发巡逻员
→ 现场确认 → 处置反馈 → 审核归档 → (误报存样本库供AI优化)
```

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|
| F-01 | 热成像火点检测 | 指挥中心 | 自动发现火情，不再等人报告 | 激光云台检测到异常高温自动生成告警，阈值可调 | P0 |
| F-02 | 可见光烟雾识别 | 指挥中心 | 烟雾是火灾前兆，早发现早处置 | 烟雾置信度>70%触发告警，阈值可调 | P0 |
| F-03 | 无人机热成像告警 | 指挥中心 | 无人机视角更大，发现地面看不到的火点 | 接收无人机实时热成像分析结果，在地图上标注 | P0 |
| F-04 | 告警分级 | 指挥中心 | 火警和一般告警不能一样处理 | 一级（火灾）红色弹窗+声音，二级橙色，三级黄色，四级灰色 | P0 |
| F-05 | 告警详情页 | 指挥中心 | 看到告警要立刻知道：什么时间、哪里、什么设备、截图是什么 | 展示告警ID、时间、设备、位置、实时视频、关联截图 | P0 |
| F-06 | 告警实时列表 | 指挥中心 | 未处理的告警要醒目，不能漏 | 按时间倒序，未处理置顶红色高亮，实时刷新 | P0 |
| F-07 | 告警自动截图 | 指挥中心 | 事后复盘时要有图有真相 | 告警触发时自动抓拍一张现场图片 | P1 |
| F-08 | 告警确认/误报 | 指挥中心 | 误报要标记，不然不知道哪些告警不准 | 确认"真实告警"或"误报"，误报图片存入样本库 | P1 |
| F-09 | 误报样本导出与模型重训 | 管理员 | 误报标了不用等于白标，要用来改进AI | 管理员可导出误报图片集，周期性提交至AI训练流水线 | P1 |

### 价值流二：环境监测闭环（传感器 → 告警 → 趋势分析）

**为什么做**：火灾往往伴随高温干旱，环境数据是预警的前哨。

```
传感器采集 → 数据入库 → 阈值判断 → (超阈值)告警 → 工单派发
→ 历史曲线 → 趋势分析
```

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|
| E-01 | 环境因子实时仪表盘 | 指挥中心 | 一眼看到当前温度风速湿度雨量，判断火灾风险 | 风速/风向/温度/湿度/雨量实时显示，超阈值红色闪烁 | P0 |
| E-02 | 环境因子超阈值告警 | 指挥中心 | 高温+大风=高风险，要自动提醒 | 风速≥6级/温度≥35℃/雨量≥20mm触发告警 | P0 |
| E-03 | 告警规则引擎 | 指挥中心 | 单一指标超标可能是误报，多指标组合才是真告警 | 预设规则：温度≥阈值AND烟雾>阈值→一级火警 | P0 |
| E-04 | 环境因子历史曲线 | 指挥中心 | 看趋势比看单点更重要，持续升温比突然高温更危险 | 最近24小时趋势折线图，支持切换时间范围 | P1 |
| E-05 | 告警聚合 | 指挥中心 | 同一个传感器10秒报3次，只处理1次就够了 | 同设备同类型10秒内告警自动合并为1条 | P1 |

### 价值流三：应急响应闭环（告警 → 工单 → 处置 → 归档）

**为什么做**：发现告警只是第一步，关键是能不能快速响应、闭环管理。

```
告警 → 自动创建工单 → 派发巡逻员 → 现场处置 → 提交反馈 → 审核归档
```

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|
| T-01 | 告警自动生成工单 | 指挥中心 | 减少人工操作，告警来了自动派活 | 一级/二级告警自动创建工单 | P0 |
| T-02 | 工单派发 | 指挥中心 | 派给合适的巡逻员，而不是随便派 | 按距离+当前负载自动推荐，管理员确认或改派 | P0 |
| T-03 | 工单列表与详情 | 指挥中心/巡逻员 | 所有人看到同一份信息，不用打电话问"你到了吗" | 状态流转：待派发→处理中→已完成→已归档 | P0 |
| T-04 | 工单实时同步 | 指挥中心/巡逻员 | PC端派单，App上立刻看到 | PC端操作后，移动端最迟30秒内可获取更新 | P0 |
| T-05 | 处置反馈（拍照+描述） | 巡逻员 | 到了现场拍个照、写两句，比打电话靠谱 | 连拍最多9张，自动水印（时间/位置/工单号），文字描述必填 | P0 |
| T-06 | 处置结果审核 | 指挥中心 | 巡逻员说"处理完了"，指挥中心确认才算完 | 提交后管理员审核通过或驳回 | P1 |
| T-07 | 处置时间线 | 指挥中心 | 每个环节花了多久，以后复盘用 | 记录创建→派发→接单→到达→完成时间戳 | P1 |
| T-08 | 超时提醒 | 指挥中心 | 工单发了没人接，要有人催 | 30分钟未接单自动提醒管理员 | P1 |
| T-09 | 人工创建工单 | 指挥中心 | 不是所有活都是告警触发的，日常巡检也要派单 | 手动创建巡检/事件工单，支持上传图片附件 | P1 |
| T-10 | 命令改派 | 指挥中心 | 派错了人，或者去的人发现搞不定，要能换人 | 管理员可将处理中的工单改派，需填原因 | P1 |
| T-11 | 工单优先级标识 | 指挥中心 | 火灾相关的工单要最醒目 | 紧急红色标签置顶，普通蓝色 | P1 |

### 价值流四：巡逻人员日常工作流

**为什么做**：巡逻员是系统的"最后一公里"，系统好不好用看他们用得顺不顺。

```
登录 → 看今日待办 → 接任务 → 导航前往 → 现场处置 → 提交反馈 → 下班
```

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|
| P-01 | 手机号验证码登录 | 巡逻员 | 巡逻员年纪可能偏大，密码记不住，手机号+验证码最友好 | 短信验证码登录，60秒有效，60秒倒计时重发 | P0 |
| P-02 | 自动登录 | 巡逻员 | 每天登录输密码太麻烦，7天免登录 | 7天内免登录，Token过期跳转登录页 | P0 |
| P-03 | 今日待办卡片 | 巡逻员 | 一打开App就知道今天要干嘛 | 待处理工单数、未读告警数 | P0 |
| P-04 | 待办任务列表 | 巡逻员 | 先处理紧急的、近的 | 按优先级和距离排序，下拉刷新 | P0 |
| P-05 | 工单详情 | 巡逻员 | 到了现场要知道：什么告警、在哪、建议怎么处理 | 告警等级/位置/地图/截图/建议 | P0 |
| P-06 | 一键导航 | 巡逻员 | 湿地没门牌号，没导航找不到地方 | 调用手机地图App自动规划路线 | P0 |
| P-07 | 开始处置 | 巡逻员 | 记录"我几点到的"，考核和工作量统计都需要 | 点击后状态→处理中，记录开始时间 | P0 |
| P-08 | 拍照上传 | 巡逻员 | 照片是现场最好的证据 | 连拍最多9张，自动水印（时间/位置/工单号） | P0 |
| P-09 | 处置结果 | 巡逻员 | 到了现场总得有个结论 | 已处理/误报/需支援/无法到达，单选必选 | P0 |
| P-10 | 工单提交 | 巡逻员 | 交活了，下一个 | 提交后状态→待审核，不可修改 | P0 |
| P-11 | 新任务语音播报 | 巡逻员 | 走路时不用掏手机看 | 收到新工单自动播报"您有新的任务" | P1 |
| P-12 | 处置描述 | 巡逻员 | 照片不能说明一切，需要文字补充 | 文字描述处置情况，最少10字 | P1 |
| P-13 | 紧急求助 | 巡逻员 | 一个人巡湿地，遇到危险要有求救渠道 | 发送求助信号(位置+照片)至指挥中心 | P1 |
| P-14 | 天气提示 | 巡逻员 | 出门前知道今天什么天气，决定带什么装备 | 显示当前温度/风速，极端天气红色警告 | P1 |
| P-15 | 快速上报 | 巡逻员 | 看到垃圾、设施损坏、可疑人员，不用走工单也能上报 | 一键上报事件，拍照+位置自动采集+简述 | P1 |
| P-16 | 短视频上传 | 巡逻员 | 有时候视频比照片更有说服力（比如火势蔓延） | 录制≤30秒视频上传 | P1 |

### 价值流五：指挥中心日常工作流

**为什么做**：指挥中心是系统的大脑，他们每天8小时坐在屏幕前，流畅度直接影响响应速度。

```
登录 → 看监控大屏 → 处理告警 → 派发工单 → 跟踪处置 → 换班交接
```

| C-11 | 一键调取周边视频 | 指挥中心 | 告警点附近有哪些摄像头，一键调出来看 | 点击告警位置，调取周边摄像头 | P1 |
| C-12 | 告警语音分级 | 指挥中心 | 不同等级的告警用不同声音，一听就知道严重程度 | 一级语音提示+紧急提示音，二级仅语音，三级/四级静音 | P1 |
| C-13 | 值班交接班记录 | 指挥中心 | 换班时不会漏事 | 自动生成交接清单（当班告警/未处理事项/设备异常/无人机状态） | P1 |

| D-02 | 航线管理 | 指挥中心 | 设定飞行路线，让无人机自动巡逻 | 创建/编辑/删除航线，航点设高度速度和动作 | P0 |
| D-03 | 定时任务 | 指挥中心 | 每天自动起飞巡逻，不用人操作 | 设置每天/每周自动起飞执行航线 | P0 |
| D-04 | KML导入导出 | 指挥中心 | 有时需要在专业地图上画好航线再导入 | 支持KML导入导出航线 | P1 |

### 价值流八：领导视察与系统展示（证明系统能用、好用）

**为什么做**：系统建好了，领导来了要能展示。展示的不是花哨的动画，是"系统完整跑起来了、遇到突发能应对"。

```
领导站到大屏前 → 看到系统运行状态 → 看一段应急演示 → 问几个问题 → 满意离开
```

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|

| V-02 | 应急演示模式 | 领导/指挥中心 | 领导想"看看到底能不能用"时，一键进入演示 | 模拟触发一条告警，全流程演示：告警弹窗→工单自动创建→地图定位→处置时间线，数据不进入正式库 | P1 |
| V-03 | 电视大屏适配 | 领导 | 同一套PC界面，在电视上打开要清晰可读 | PC界面在1920×1080至3840×2160分辨率范围内所有元素清晰可读，支持浏览器全屏显示 | P1 |
| V-04 | 大屏默认布局 | 领导 | 电视打开后直接看到核心信息，不用操作 | 电视打开时默认进入"概览模式"：左侧GIS地图+中间视频+右侧数据面板 | P1 |
| V-05 | 告警分级弹窗 | 指挥中心/领导 | 一级告警必须醒目，四级安静处理 | 一级中央弹窗+语音，二三级右侧滑入，四级列表高亮 | P1 |

### 价值流九：系统管理与安全（保证平台稳定运行）

**为什么做**：系统三天两头出问题，没人会用。

| 编号 | 功能 | 谁用 | 为什么做 | 验收标准 | 优先级 |
|:----:|:----|:----|:--------|----------|:------:|
| S-01 | 账号密码登录 | 所有人 | 最基本的安全准入 | 用户名密码登录，连续5次失败锁定10分钟 | P0 |
| S-02 | 密码复杂度策略 | 管理员 | 弱密码是最大安全隐患 | 至少8位，含大写/小写/数字/特殊字符中至少三类 | P0 |
| S-03 | 用户管理 | 管理员 | 人来了能加，人走了能删 | 添加/编辑/禁用/删除用户 | P0 |
| S-04 | 角色管理（RBAC） | 管理员 | 不同人看到不同东西，不能乱 | 预设4种角色，自定义角色和菜单权限 | P0 |
| S-05 | 区域权限过滤 | 管理员 | 巡逻员只看自己区域的工单，不该看到别的区 | 巡逻员只能看到本区域告警和设备 | P1 |

| S-07 | 告警阈值配置 | 管理员 | 天气变了、季节变了，阈值要跟着调 | 配置温度/烟雾置信度/风速/雨量告警阈值 | P0 |
| S-08 | 推送方式配置 | 管理员 | 不同的告警用不同方式通知 | 配置推送渠道（App推送/短信），按告警等级配置不同方式 | P1 |
| S-09 | 系统参数备份与恢复 | 管理员 | 系统崩了能恢复，不至于从头来 | 一键备份，从备份文件全量恢复，需二次密码确认 | P0 |
| S-10 | 日志查询与导出 | 管理员 | 出了问题要查日志 | 按时间/用户/操作类型检索，支持导出CSV | P1 |

## 第四部分：非功能性需求（保证平台真能用）

### 4.1 性能（保证"用起来不卡"）

| 编号 | 指标 | 为什么是这个值 | 验收标准 |
|:----:|:----|:--------------|:---------|
| N-01 | 内网视频首屏 ≤3秒，4G ≤5秒 | 4G走公网，物理限制，3秒不现实 | 实测验收 |
| N-02 | 录像查询 ≤3秒 | 查个录像等半天，没人愿意用 | 实测验收 |
| N-03 | 告警端到端 ≤5秒 | 超过了火可能就烧大了 | 从设备触发到PC弹窗计时 |
| N-04 | 无人机直播 ≤2秒 | 飞在天上看地面，延迟大了没意义 | 实测验收 |
| N-05 | 并发 30PC + 50移动 | 湿地管理站人员规模通常不大，按实际人数上浮估算 | 压测验收 |

### 4.2 可靠性（保证"不关键时刻掉链子"）

| 编号 | 指标 | 为什么是这个值 | 验收标准 |
|:----:|:----|:--------------|:---------|
| N-06 | 系统可用性 99% | 年均故障≤87小时，湿地管理不是银行系统，99%够用 | 连续运行30天统计 |
| N-07 | 告警不丢失 | 漏一个告警可能就漏一场火 | 本地缓存+恢复补传机制 |
| N-08 | 数据库每日备份 | 万一崩了不能丢数据 | 自动全量备份，保留7天 |

### 4.3 安全（保证"不被黑"）

| 编号 | 指标 | 为什么是这个值 |
|:----:|:----|:--------------|
| N-09 | 视频流加密传输 | 湿地画面不该被人随便看 |
| N-10 | bcrypt密码存储 | 密码明文存=自杀 |
| N-11 | 防SQL注入 | 最基本的Web安全要求 |
| N-12 | API Token鉴权 | 没有认证的接口就是敞开的门 |
| N-13 | 日志只追加不可删 | 出事了能查是谁干的 |
